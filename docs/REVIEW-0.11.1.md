# Glossleaf 0.11.1：动画、操作与多文献自查修订

日期：2026-11-01。基线 0.11.0。此次以稳定现有界面为目标，不再改变两端工具分组、纸墨配色和阅读布局。下表区分本次确认的问题与修复结果。

## 确认的问题与处理

| 触发方式 | 原问题 | 本次处理 |
|---|---|---|
| 书府的已打开文献标签 | 通用按钮规则与单标签铺满规则影响关闭键；单个标题可能拉长整行；书府却仍把某篇标成正在显示的阅读页 | 隔离标签按钮样式，关闭区域 24×24、无独立粗边框；书府标签限宽；作为已打开文献导航，不冒充当前阅读页签 |
| 保存期间连续切标签或关多篇 | busy 状态直接丢弃后续请求；键盘连按重复依据旧活动文献计算 | 导航串行处理，待执行的打开操作采用最后意图，关闭请求逐项完成；失败保留当前文献并阻止旧请求继续切走 |
| 连续关闭后阅读器正在替换 | 旧组件控制器可能被新文献身份引用，存在把 A 的状态写到 B 会话的风险 | 控制器显式绑定文档版本 ID；只保存匹配的文献；提交批注后读取最新界面状态 |
| ⌘/Ctrl+Shift+F 等返回入口 | 有路径直接切书府，绕过批注提交；还可能被阅读器的普通查找先处理 | 全部走统一保存入口；全局快捷键在合适的捕获阶段处理，成功后才聚焦书府搜索 |
| 在侧栏输入后点笺注／札记、目录、阅读模式或另一批注 | 有分支直接替换编辑器；侧栏编辑仍沿用旧浮层“点外部关闭”行为，造成重复提交与位置恢复竞争 | 侧栏编辑不因随意点击正文关闭；显式离开先提交，成功后改变面板或模式；失败保留可编辑草稿 |
| 新批注未写完时快速换颜色 | 颜色保存绕过文本保存队列，可能与首次创建并发 | 文本、颜色和自动保存共用队列，新批注保持同一记录；离开也等待该队列 |
| 打开文献、查找定位或从札记返回时马上手动滚动／翻页 | 旧的延迟恢复和重试还在运行，会把新位置拉回；段落同步动画不能被直接滚动取消 | 恢复、重试和定位使用请求版本；新的手动操作取消过时动作；滚轮、触摸、点击和键盘可中断同步滚动 |
| 标签异步切换后使用方向键 | 焦点仍可能留在旧组件，下一次按键落到正文翻页 | 新标签完成挂载后恢复键盘焦点；连续键依据请求目标计算 |
| 文档加载尚未完成 | 页数可能短暂退到 1/1；缓存页码允许在未加载时操作并被钳制到第一页 | 缓存已知总页数，未知用“—”；加载期间阅读工具不可交互，顶部标签和关闭仍可用 |

## 动画规则

阅读页不再用位置平移动画进场，侧栏和设置内容也不反复位移。新页面仅短暂透明度过渡；段落同步滚动缩短为 160ms，直接输入可立即取消。批注关闭只在用户没有重新滚动时恢复原阅读点；已经手动改变位置，就保留新位置。遵循系统“减少动态效果”。

此次没有用延长动画遮盖保存或文件加载。切换前需要等待的是真实批注／阅读记录提交，待执行操作仍可登记；错误会保留当前编辑状态。

## 验收方法与结果

本版新增 scripts/glossleaf-interaction-audit-e2e.cjs，使用原生 Chromium 鼠标按下／抬起事件，并在临时服务通道中人为延迟保存与读取响应。它覆盖：

- 书府单标签限宽、关闭区域 24×24、无粗边框、无错误当前页选中态。
- 点正文不再意外关闭侧栏编辑器；颜色和自动保存只有一条批注记录。
- 输入后立即换侧栏页签、全局搜索，文字先提交。
- 慢保存期间连续 B→A 请求最终停在 A，连续 Ctrl+Tab 正确累计目标。
- 异步换文献后焦点在当前标签；保存中连续关闭两篇都会完成，B 的阅读记录不被 A 覆盖。
- 延迟 reading:get 返回后不覆盖新翻页；关闭批注不覆盖手动滚动；滚轮取消段落同步动画。
- 系统减少动态模式生效，无正文位置平移动画。

多文献与布局回归还覆盖六个长标题、中英文窄窗口、独立页码／缩放／旋转、保存冲突及恢复。底层 93 项检查、类型检查和生产构建通过。完整本版结果以 docs/evidence-0.11.1/verification.json 为准；历史 evidence 不代表新增验证。

测试使用临时文库，未修改个人书库、原 PDF 或 API Key；未发起真实付费模型请求。应用为独立 0.11.1，保留 0.11.0。

## 仍然存在的边界

本轮没有增加 OCR、并排 PDF、多窗口或整套标签跨重启恢复；多文献仍是同一窗口内切换。非活动 PDF 释放后，切回需要重新读取本地原件。当前设备和测试文件通过，不等于穷尽所有 PDF／硬件组合。真实云模型和外部元数据服务未使用个人凭据在线验收。

macOS arm64 本地预览包使用 ad-hoc 签名，未做 Developer ID 公证。数据库仍是 schema 7，本版无数据迁移。
