## 1. 这个项目是什么

一个 macOS 桌面文献管理器，定位是「面向中文母语研究者的本地文献工作台」。差异化在**中文母语者读外文文献**（段落联动译文面板、选区翻译、术语表）。

**权威设计文档是 `DESIGN.md`（v3.0，1375 行）**。它是产品的唯一基线，代码有偏离的地方都记在 `docs/verification.md` 的「与 DESIGN.md 的偏离」表里。**先读 DESIGN.md 的 §9（技术架构）、§10（领域模型）、§11（Zotero 导入）、§17（里程碑）四章**，其余按需查。

## 2. 五分钟跑起来

环境要求：macOS（arm64 优先）、Node ≥ 22、pnpm ≥ 10。

```bash
cd jian
pnpm install
pnpm build          # 三入口构建：main / preload / renderer，外加 data-service
pnpm start          # 或 ./scripts/run.sh
```

开发模式：

```bash
./scripts/run.sh dev
```

> **`scripts/run.sh` 不是可选项。** 见下一节。

## 3. 两个必踩的坑

### 坑一：`ELECTRON_RUN_AS_NODE=1` 会让 Electron 退化成纯 Node

某些宿主环境（比如 Electron 应用启动的子进程）会继承这个变量。症状很隐蔽：

```
TypeError: Cannot read properties of undefined (reading 'registerSchemesAsPrivileged')
    at registerDocumentScheme (...)
Node.js v24.22.1          ← 栈尾出现 Node 版本号就是它
```

判断方法：如果报错里 `electron.protocol` / `electron.app` 是 undefined，就是这个问题。

**所有启动命令都必须走 `scripts/run.sh`**，它内部是 `env -u ELECTRON_RUN_AS_NODE`。

### 坑二：构建失败会静默，你会在跑旧包

开发期我踩过：`pnpm build >/dev/null` 失败后仍然用旧的 `out/` 启动，连续三次截图是同一张图，误以为是 CSS 或 React 的问题，绕了很久。

**规则：每次构建都要看输出，确认出现 `✓ built in`。** 判断是否跑了新代码，看 `out/renderer/assets/index-*.js` 的哈希是否变化。

## 4. 架构速览

```
渲染进程（sandbox: true）
  ├─ 文库 / 阅读器 / 翻译 UI
  ├─ PDF.js 页面绘制（worker 独立打包）
  └─ 只通过 window.jian.* 具名方法通信，拿不到 ipcRenderer
        │
   preload（CJS 单文件）
        │  Result<T> 包装，错误不抛到渲染层
        ▼
主进程
  ├─ 窗口、菜单、jian:// 文档协议（token + Range）
  ├─ 翻译任务调度（未实现，M3）
  └─ 数据服务客户端（spawn utilityProcess，请求 ID + 超时）
        │
   独立数据服务进程（utilityProcess）
        └─ 全应用唯一的 SQLite 写连接
```

**关键约束（改代码时别破坏）**：

1. **主进程不碰数据库。** 所有数据操作走 `src/main/data-client.ts` → `src/data-service/index.ts`。
2. **渲染进程拿不到文件路径。** 打开 PDF 走 `documents:open`，主进程校验后签发一次性 token，URL 形如 `jian://doc/<token>`。
3. **附件内容寻址。** `blobs/<sha前2位>/<sha次2位>/<sha256>.<ext>`，同一内容只存一份。
4. **所有 `app_*` / 业务表用 UUID，外部身份只进 `origin_map`**（四元：来源实例 + 来源库 + 对象类型 + 外部 key）。**绝不用 Zotero 的数字 ID 做主键。**

## 7. 调试手法

### 7.1 无头截图（改 UI 时最有用）

```bash
JIAN_VIEW=library JIAN_CAPTURE=/tmp/shot.png JIAN_CAPTURE_DELAY=5000 \
  ./scripts/run.sh
```

- `JIAN_VIEW` = `library` | `reader` | `probe`
- `JIAN_QUERY="zotero=1"` 打开 Zotero 导入对话框
- `JIAN_QUERY="zotero=report"` 直接展示最近一次导入报告
- 截图时会在 stdout 打印 `[capture] {"modal":..., "flag":...}`，可用来确认对话框是否真的挂载

### 7.2 开发用环境变量

| 变量 | 作用 |
|---|---|
| `JIAN_LIBRARY_DIR` | 指定文库目录。**调试时务必用独立目录**，别碰真实文库 |
| `JIAN_ZOTERO_DIR` | 指定 Zotero 数据目录（默认 `~/Zotero`） |
| `JIAN_ZOTERO_IMPORT=1` | 启动即跑一次迁移并打印报告 |
| `JIAN_IMPORT=/path/a.pdf` | 启动即导入 PDF |

### 7.3 直接查库

文库是普通 SQLite，可以用 `sqlite3` 只读检查：

```bash
sqlite3 "file:$JIAN_LIBRARY_DIR/jian.sqlite?immutable=1" ".tables"
sqlite3 "file:$JIAN_LIBRARY_DIR/jian.sqlite?immutable=1" \
  "SELECT type, title FROM item LIMIT 10;"
```

> 注意：如果库正在被应用打开，用 `immutable=1` 会看不到未 checkpoint 的 WAL 内容。关掉应用再看，或去掉 `immutable=1`。

### 7.4 关键调试入口

- 数据服务出错：`[data-service]` 前缀打在 stderr
- 渲染层错误：主进程会转发 `[renderer:error]` / `[renderer:warning]`
- 迁移过程：`import_run` 表里有每次 run 的状态、计数、错误


## 11. 建议的接手顺序

1. **先跑起来**：`pnpm install && pnpm build && ./scripts/run.sh`，确认能看到空文库
2. **读 DESIGN.md §9–§11**，再看 `docs/verification.md` 的偏离表
3. **导入一点数据**：拖一个 PDF 进窗口，或指向自己的 Zotero
4. **从 M3 开始**：这是最大的一块，也是产品差异点
   - 先接 PDF.js 标准文本层（`TextLayer` 类），验证选区坐标
   - 再做段落分析（`src/renderer/src/reader/layout/` 目录还没建）
   - 最后做译文面板与选区翻译
5. **不要动的地方**：数据服务的单写连接、`origin_map` 的四元标识、`document_version` 的「文件或授权二选一」约束。这三处动了会连锁返工
