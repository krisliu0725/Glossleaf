## 本轮结果

从 M2 交接包继续实现 M3：PDF 标准文本层与链接、按段对应的译文面板、选区流式翻译、云端兼容接口和 Ollama 适配器、术语表、语境缓存、任务取消/暂停/继续、摘录保存与原文回跳。原文阅读不依赖翻译配置。

界面沿用既定纸墨配色。译文 16px/1.75 行高，可选、可复制；段落操作使用文字入口。窄窗口采用上下阅读工作区；设置/术语模态支持 Esc、Tab 焦点约束与关闭后焦点返回。

## 修复的交接遗留问题

1. 现有备份核验把任何 schema >1 的备份拒绝，当前文库已是 v2。改为使用实际支持版本，并验证恢复。
2. 备份完成后的清单之前读取活库，翻译持续写入时可能与备份不一致。改为从备份副本读取计数与文件清单。
3. 原阅读器以提前加载页的 IntersectionObserver 结果充当当前页，预取页会污染进度。改为从实际阅读视口计算当前页并保存页内偏移。
4. 补充 CSP 响应头、权限默认拒绝与主 frame 校验；端点改变不复用旧密钥。
5. PDF.js 6 的 viewport API 与旧示例不同，采用实际固定版本的点变换接口及标准文本层样式，包括旋转规则。
6. 分段使用未旋转的规范页面空间，显示、选区与标注使用实际 viewport，避免旋转页内容被倒序串接。

## 关键行为

- 缓存包含选区/段落模式、源语设置、目标语言、实际上下文、命中的有效术语、端点、模型、参数、提示版本与占位符映射。
- 模型必须正常结束才能提交成功缓存；长度截断、过滤、断流、占位符缺失/重复不会伪装成成功。
- 共享请求的单个订阅取消不影响其他视图；全部取消才尝试中止底层传输。已发送请求可能仍被服务端计费。
- 后台文档任务独立于阅读器，冻结引擎与术语快照；完成单元有检查点。应用重启后等待用户继续。
- 交互请求保留一个并发槽位；后台最多占用一个槽位。
- 成功保存的译文进入永久记录，缓存与任务不是用户摘录的唯一存放处。
- 跨页摘录逐页存坐标，评论和译文归同一条摘录。重新打开仍可回跳原页区域。
- 密钥按协议及端点分别保存在 `.secrets/profiles.enc` 的系统加密密文中；备份不包含密钥。文献与备份本身没有因此被加密。

## 已知边界

本轮不是对任意 PDF 的完整版面理解器。启发式分段已覆盖合成双栏、常规段落、参考文献与旋转样本；表格、数学、竖排、罕见字体或错误编码可能需要手动选择。保留原 PDF 与原始文字，不通过重排隐藏错误。扫描页明确说明无可提取文字。

未使用真实用户文献和真实服务密钥。模拟译文只验证协议与交互，不代表语言质量。复杂论文的人工段落 F1、多语覆盖、大规模内存性能和完整 VoiceOver 验收仍需真实样本评估。

0.3.1 增加 Google 原生 Gemini / Gemma 适配器；保留云端兼容适配器与 Ollama 原生适配器。兼容服务必须支持当前 Chat Completions SSE 协议与正常结束语义；无法保证任意自称兼容的端点都工作。“测试翻译”使用界面草稿配置和固定示例句，不发送当前文献。旧的测试连接 IPC 保留兼容。
